Three modules, one orderbook

Everything a perps trader wishes the exchange shipped.

Each engine is a pure, unit-tested TypeScript module. The same code runs against an in-browser matching engine in Demo mode and against Strike's REST + WebSocket API in Live mode — only the adapter changes.

01

CLOB Grid Studio

A neutral grid — buys below the mark, sells above, the level nearest the mark left empty so the sides never collide. Geometric or arithmetic spacing, 4–60 levels.

  • Every rung placed in one POST /v2/orders/batch, post-only, with X-Builder-Fee-Bps
  • Fill → counter take-profit one rung away for the filled quantity; exit fill → entry re-armed
  • Net profit per round trip shown after maker fees and builder fee
  • Whale-wall radar and VWAP slippage probe on the live top-20 book

02

Funding Harvester

Strike pays funding hourly. Vektor ranks every market by annualised funding (r × 24 × 365), then sizes a 1:1 perp hedge against spot you already hold.

  • Liquidation price of the hedge from the market's real margin tiers
  • Sliced IOC entry that keeps the builder fee (Strike's TWAP drops it)
  • Rule C: unwinds automatically after 3 consecutive adverse funding hours
  • Live tracker: perp uPnL vs funding collected
/price/v2/premiumIndex!markPrice@arrmargin_tiers
03

Aegis Liquidation Shield

Computes distance-to-liquidation for every open position with the same formulas as Strike's engine and escalates before the engine gets there.

  • Rule A < 8% buffer: cancel resting buy rungs to free margin
  • Rule B < 5% buffer: reduce-only market trim of 25%
  • Per-symbol cooldown + pending-trim flag — never fires twice for one episode
  • PANIC button: cancel everything, flatten with close_position

Module deep dive

Designed around how Strike's engine actually behaves.

Writes are async — a 201 pending means sequenced, not filled. Rejections like order_would_match_immediately arrive on the user stream. Vektor's engines are built for that reality, not a toy exchange.

01 / GRID STUDIO

Order roles live in the client ID.

Every rung order is tagged vektor-grid-<id>-<rung>-<e|x>-<seq>. When a fill comes back on the user stream, the engine knows exactly which rung and whether it was an entry or an exit — even after a reconnect or a page reload.

e BUY fills at rung i → place exit SELL at rung i+1 for the filled qty
e SELL fills at rung i → place exit BUY at rung i−1
x fills → round trip booked, entry re-armed; never stacks on a rung that already rests the same side
CANCELED / REJECTED / EXPIRED → rung freed, logged with the engine reason
02 / FUNDING HARVESTER

Delta zero, funding positive.

Positive funding means longs pay shorts every hour at HH:00 UTC. Hold 10,000 ADA in your own wallet, short 10,000 ADA-perp at 2x, and you collect funding regardless of direction. Vektor shows the hedge's liquidation price so a rally can't surprise you.

APR = |hourly rate| × 24 × 365 — Strike funds hourly, not every 8h
LP = (EP − (iso + MA)/size) / (1 + MMR) from the live margin tiers
Entry N IOC limit slices through /v2/orders/batch — builder fee attached
Exit Rule C unwind, or one-click reduce-only flatten
03 / AEGIS SHIELD

Programmable, not panicky.

A naive shield fires a trim on every mark tick while you're under the threshold. Aegis tracks a per-symbol cooldown and a pending-trim flag, resets the episode only once you're back to SAFE, and logs every decision with the buffer that triggered it.

RULE ABuffer < 8% → cancel every resting BUY rung on that symbol. Frees locked order margin immediately. Fires once per episode.
RULE BBuffer < 5% → reduce-only market trim of 25% of the position. Cooldown 15s, blocked while a trim is pending.
RULE CFunding flipped against the hedge for 3 consecutive hours → unwind the perp leg.
PANICCancel all orders on every symbol, flatten every position with close_position: true. Confirmed, then immediate.

Builder code economics

A 12-rung grid is 12 attributed orders. Every flip is one more.

Strike's Builder Codes pay a per-fill fee (X-Builder-Fee-Bps, 0–100 bps) to the integrator. Market-order buttons generate one fill. A grid generates continuous maker flow for as long as the market ranges. Vektor is built so that all of it is attributed.

Order pathHonours X-Builder-Fee-BpsVektor uses it for
POST /v2/orders/batchYesGrid deployment, counter orders, hedge slices, shield trims
POST /v2/order/strategyYesBracket TP/SL (reference app)
POST /v2/grid/bot (native)No — no builder code at allHead-to-head comparison only
POST /v2/algo/twapNoReplaced by Vektor's sliced IOC entry
POST /v2/order/replaceNoAvoided — cancel + batch instead

Live telemetry in the app header: volume routed, fills, and cumulative builder fees — so the business model is visible on screen, not just in a pitch deck.

FAQ

Honest answers.

Does it run 24/7 if I close the tab?

Not yet. Like the reference app, the API wallet key lives in browser memory and the counter-order loop and shield run while the page is open. Grids persist locally and reconcile against open orders when you come back. A Node worker that holds the key is the obvious next step and the engines are already headless-ready (zero React dependencies).

Why not just use Strike's native grid bot?

It exists and Vektor can launch it for comparison. But it ignores X-Builder-Fee-Bps entirely, is arithmetic-only, and the client can't shield its orders. Vektor's grid pays the builder on every fill — that's the business.

Where does the backtest data come from?

Mainnet /price/v2/klines, which is public. Testnet candles are flat because nothing trades there. The backtester walks each candle open → low/high → close so every rung a wick touched gets filled — that's optimistic on thin books and the UI says so.

What's the 50 bps builder fee from the original plan?

Dropped to 10 bps by default. At 50 bps a round trip pays 1% in builder fees alone, which eats most grid spreads. The design card shows net-per-cycle after fees so you can see exactly where the break-even is.

Is funding every 8 hours?

No — Strike funds hourly at HH:00 UTC, and r on markPriceUpdate is the hourly rate. Vektor's APR math, hedge tracker and Rule C all use the hourly convention.

Open the terminal in Demo mode, deploy a grid, hit "Flash crash −12%", and watch Aegis cancel the buys and trim the long before the simulated engine would have liquidated it. Then switch to Live.

# Vektor worker (headless, 24/7)

Runs the same grid + shield engines as the terminal, without a browser. The API wallet key lives in the environment, state persists to a JSON file, and fills that happened while the worker was down are backfilled from `GET /v2/history/fill` on start.

```bash
cp worker/grids.example.json worker/grids.json      # edit ranges
export STRIKE_API_PUBLIC_KEY=...                     # from Builder Connect (the terminal logs them on connect)
export STRIKE_API_PRIVATE_KEY=...
export BUILDER_FEE_BPS=10
npm run worker
curl localhost:8787/                                 # status JSON: grids, positions, shield log, telemetry
curl -X POST localhost:8787/stop/ADA-USD             # stop one grid (cancels its rungs)
curl -X POST localhost:8787/panic                    # cancel everything, flatten every position
```

Defaults point at mainnet (`api.strikefinance.org`), where builder codes are registered. Set `STRIKE_API_URL=https://api-v2-testnet.strikefinance.org` for testnet - note testnet does not know mainnet builder codes and its order books are mostly empty.

What it does every cycle:
- **Fills** from `/ws/user-api` → grid counter orders through `/v2/orders/batch` with `X-Builder-Fee-Bps`.
- **Shield** every 2 s on positions enriched with the reference liquidation math (Rules A/B, cooldown, pending-trim).
- **Watchdog** every 4 s: an order accepted with `201` but with no user-stream event within 8 s is looked up with `GET /v2/order`; a `404` means Strike silently dropped it and the rung is freed.
- **Reconcile** on every (re)subscribe against `/v2/openOrders`; REST re-sync every 60 s.

## Getting the keys

1. **Builder code** - self-service at <https://app.strikefinance.org/builder-codes>: register, pick a fee share (max 100 bps). Fees are credited to your Strike balance on every fill and withdrawable any time ($5 min, $1 flat fee). Docs: <https://docs.strikefinance.org/api/builder-codes>.
2. **API wallet** - generate an Ed25519 keypair and register the public key at <https://app.strikefinance.org/api-keys> (raw 64-hex keys, not SSH format). API wallets can trade but never withdraw or deposit. Docs: <https://docs.strikefinance.org/api/getting-started>.
3. Put the pair in `STRIKE_API_PUBLIC_KEY` / `STRIKE_API_PRIVATE_KEY`. For builder-fee attribution the account must have approved your builder code (Builder Connect in the terminal does that once).

Keys generated by Builder Connect in the browser live in memory only; if you want the worker and the terminal to share one API wallet, register the key on the API Wallets page instead of letting the browser generate a throwaway one. `verify-signature` revokes the account's previous API wallets for the same builder code.
